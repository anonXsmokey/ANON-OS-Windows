# ANON OS Windows — Repository Experience

The repository itself is part of the product identity. It should feel like an engineering command center, not a document archive.

## Visual direction

- strong ANON branding
- dark, high-contrast gaming aesthetic
- concise sections with visual hierarchy
- architecture diagrams
- milestone progress
- benchmark dashboards as real data becomes available
- screenshots/GIFs from actual builds, never fabricated mock evidence
- prominent navigation between Build, Performance, Gaming, Control Center, AI, Compatibility and Recovery

## Information hierarchy

The README is the front door. Detailed technical material belongs in focused documents. Large walls of prose should be replaced with diagrams, tables, status cards, and linked specifications whenever the information benefits from visual presentation.

## Future interactive surfaces

- GitHub Pages project site
- live benchmark dashboard
- hardware compatibility explorer
- game compatibility explorer
- release/build dashboard
- installation screenshots
- Control Center previews generated from real builds

## Evidence rule

Never represent a concept mockup, simulated benchmark, or untested compatibility claim as a finished ANON feature. Visual polish must increase clarity, not hide uncertainty.
