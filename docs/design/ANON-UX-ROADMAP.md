# ANON-OS UX Implementation Roadmap

This roadmap turns the ANON visual direction into product work. Fedora/GNOME is an interaction reference only; ANON remains a Windows-based distribution.

## Phase 1 — Shell foundation

- Premium ANON desktop surface
- Top-bar and launcher navigation
- Persistent themes
- Wallpaper service
- Reduced-motion support
- Live CPU/memory telemetry
- Gaming mode state
- ANON Files / Apps / Games entry points

## Phase 2 — System experience

- Full ANON Control Center
- Settings shell with category navigation
- Notifications center
- Search / launcher command model
- Appearance editor
- Wallpaper picker and slideshow
- Account/session surface
- Power, network, Bluetooth and display quick controls

## Phase 3 — Premium visual layer

- Custom ANON icon system
- Curated wallpaper packs
- Animated boot/lock/login surfaces
- Consistent micro-interactions
- Window transitions and focus states
- Theme-specific surfaces and accent states
- High-DPI and ultrawide layout validation

## Phase 4 — Installer experience

- ANON WinPE boot surface
- ANON preflight
- ANON disk selection
- ANON install progress
- ANON configuration profiles
- First-boot personalization
- Recovery entry

## Phase 5 — AI and gaming

- ANON AI shell surface
- Local Ollama provider
- Secure cloud-provider gateway contract
- Game library and launch surface
- Game-specific profiles
- Performance overlay and session telemetry

## Definition of done

A feature is not considered complete because it compiles. It must be visually coherent, keyboard/mouse accessible, responsive at common resolutions, persist user preferences where appropriate, respect reduced-motion settings, and survive a clean VM install/reboot test when it affects the installed system.
